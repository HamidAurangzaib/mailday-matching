An admin (me or a VA) logs in on Friday, sees all unmatched children, runs AI-powered match suggestions, approves or rejects each suggestion, and confirms matches. Confirmed matches write to the database and trigger external email notifications. That is the entire job of this app.

- Maximize shared interests — the more overlap the better.
- Geographic diversity is a soft preference — different states is better than same state but never a hard rule.
- Never match a child with someone they have previously been matched with.

**The matching flow:**
1. Admin opens the app and sees the Unmatched Queue — all children with match_status = Unmatched, grouped by age band — Minis pool (Minis + Homeschool Minis ages 3-6) and Core pool (Core + Homeschool Core ages 6-12)
2. Admin clicks Run Matching
3. App sends all unmatched children to the Claude API with a prompt that applies the matching rules above and returns ranked match suggestions with reasoning for each suggestion
4. Admin sees each suggested match: both children's names, ages, tiers, states, shared interests, and Claude's reasoning
5. Admin clicks Approve or Reject for each suggestion
6. Approved matches: create a record in the Matches table, update both children's match_status to Matched, populate shared_interests on the match record
7. Rejected matches: child stays in the Unmatched queue for next Friday
8. After all approvals: app displays a summary of matches confirmed this session

- When a rematch is requested, match_guarantee_start_date resets to today
- The app checks daily: any child with match_status = Unmatched where match_guarantee_start_date is 18 days ago → show a yellow warning badge in the Unmatched Queue

3. Match History — all confirmed matches, searchable by child name, filterable by age band and date range
